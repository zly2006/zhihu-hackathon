# V3.3 叙事 Agent 交接说明

本次交付只扩展叙事层，不修改 UI、World Reducer 或既有 `LifeApp.tsx`。所有世界状态变化仍必须由既有 World Simulator 与 reducer 完成。

## 已交付

- NPC 主动事件策略：`lib/game/npc-proactive-event-policy.ts`
  - 将服务端 `NpcAgentDirective` 转为最多两条、带去重 ID 的公开邀请卡。
  - 支持主动联系、情绪求助、关系谈话、目标邀约和关心主角；低落 NPC 使用 `seek_support`，但私密意图不会发送到客户端。
- Narrative Director 节奏：`lib/game/narrative-pacing.ts`
  - 使用已完成章节数形成稳定六拍：`setup → bonding → conflict → turning_point → climax → aftermath`。
  - 导演 prompt 与校验器共同要求当前节拍对应的场景功能，高潮须有公开的高压事件、紧急线索或关系冲突作为依据。
- 对白质量：`lib/game/dialogue-voice-card.ts` 与 `dialogue-writer.ts`
  - 从公开的说话方式、人格、价值观和表层情绪生成 Voice Card。
  - 拒绝私密状态原文泄漏；拒绝未出现在场景 `characters` 的角色发言。
- 原创赵冷 Demo：`lib/narrative/zhao-leng-demo.ts`
  - 全员成年人、Teen 分级、无露骨内容；四阶段共 12 个场景节拍、三个结局和一次性隐藏事件。

## 玩法接入契约

`POST /api/narrative/experience` 是只读预览接口。请求：

```ts
{
  chapterId: string;
  state: WorldState;
  decision: ChapterDecision;
  recentEvents?: SimulationEvent[];
  deliveredDirectiveIds?: string[];
  span?: 1 | 3;
}
```

响应含 `proactiveEvents`、不含私密意图的 `publicDirectives`、`directorBrief` 和 `pacing`。

玩法/UI 负责人接入时应：

1. 显示 `proactiveEvents` 的 `preview` 与 `suggestedAction`，并将已显示的 `directiveId` 随存档保存，以便下次请求传回 `deliveredDirectiveIds`。
2. 玩家回应后，将回应文本作为下一次既有 `/api/chapter/simulate` 的行动提交；不要在 UI 直接改关系、线索或世界状态。
3. `sceneHook` 只用于构造 Scene Runtime 的呈现上下文；最终事实仍以 World Simulator 输出的 canonical `SimulationEvent` 为准。

## 赵冷稳定身份

Demo 使用 `npc-zhao-leng` 作为稳定角色 ID。这需要视觉与 NPC 生成负责人确认：在创建该角色时使用同一 `characterId` 或在 `visual.avatarId` 中完成显式映射。不要按显示名“赵冷”做字符串匹配。
