## 2. 验证过程中发现并已修复的问题

| 问题 | 根因 | 修复 |
|---|---|---|
| `events[0].createsThreadLabels 必须是数组` | 模型抄写长 UUID 时截断，导致 CharacterChange 引用不存在的角色；重试时又省略可选字段 | 引入短别名系统（C#/R#/E#/T#/G#/H#/I#），模型只引用别名，服务端映射回真实 id；可选字段改容错 |
| `大模型未返回完整 JSON 对象` | `max_tokens=3200` 不足以容纳世界推演完整输出（4-8 事件 + 3-6 记忆 + 摘要），JSON 被截断 | `callGameModel` 增加 `maxTokens`/`timeoutMs` 可配置；世界推演/小说设为 8000/180s |

修复后全量 104 项冒烟测试 + lint + build 持续通过。

## 3. 用户反馈记录（待办）

### 反馈 1：UI 页面过于简陋

- **现状**：功能性 UI（人物卡/关系卡/小说阅读/时间轴/证据卡均为朴素样式）。
- **建议方向**：
  - 视觉小说感增强（方案 §27.3）：头像/立绘占位、状态栏、关系变化动画与数值反馈、关键事件时间轴可视化；
  - 章节阅读体验：更优排版、场景切换动效、章节标题氛围；
  - 落地优先级：Phase 6 遗留项，V1 内可先做"头像占位 + 视觉分层 + 动效"，重设计语言可纳入 V2。

### 反馈 2：小说缺少吸引读者的阅读兴趣 —— 建议收集优秀小说/作者语料训练大模型

- **现状**：Novel Writer 由通用指令模型生成，文风偏平、叙事张力不足。
- **建议方向（分两层）**：
  1. **短期（不改模型）**：强化 Novel Writer 的叙事 Prompt——引入优秀网文/文学的"文风参考样例"（借鉴现有 `event-style-reference.ts` 的做法，给模型提供节奏/张力/对白示范，而不是语料全文）；增加"钩子句/章节悬念"约束；把"阅读体验"作为 Novel Writer 的明确输出标准。
  2. **中期（模型侧）**：收集高质量小说/作者语料（需注意版权合规，优先使用公开授权或自建语料），构建**微调数据集**对小说模型做 LoRA/全参微调，或使用更强的写作模型/更大的 `max_tokens` + 分场景生成。
  3. **数据合规提示**：收集网上小说训练模型涉及版权，须确认授权/许可（如仅用同人免费授权、CC 协议或自购版权），避免侵权风险。
- **归属**：属于方案 §41 的 V2 方向（模型升级），不阻塞 V1 MVP 验收。
