## 摘要

知乎沉淀了中文互联网最密集的"人生经验"——关于选专业、换城市、转行、要不要读研、要不要留下。但这些经验以**答案**的形态存在，用户消费它的方式是"读"，读完即走。**读别人的答案，并不能让人更会做自己的选择。**

《假如我们的人生》把这个结构翻译了一次。知乎的最小单元是「一个问题 → 若干回答 → 回答背后的人」；视觉小说的最小单元是「一个困境 → 若干选择 → 选择背后的人」。**两者是同构的。** 我们让玩家进入一段人生阶段，与四位由知乎答主公开内容构成的 AI 化身同行，在具体事件里做出选择，并在剧情之外与化身持续对话。

产品的三个支点：

1. **内容是真的。** 每一个人生困境的每个选项，背后都挂着真实知乎回答作为事实源，可点击回到原文；选项下方直接展示"知乎上也有人这么选"的答主。
2. **关系是硬的。** 关系不是单一好感度，而是亲密、信任、冲突、承诺四轴；好感度决定的是**对方愿意向你透露到哪一层**，而不是一个爱心条。
3. **后果是算出来的。** 人生选择的结算由程序完成，AI 只负责把结果讲述成故事——**AI 无法为了讨好玩家而放水**。

我们不制造"答主的数字替身"，只制造"答主公开观点的可交互索引"。**温度来自表演，事实来自原文。**

一句话介绍：**你甚至可以在知乎玩galgame！**

预期价值：对用户，把"翻五十个回答"压缩成"活一遍"；对答主，内容从被阅读变成被需要；对知乎，存量优质内容获得新的消费场景，并获得一条**由游戏产出反哺社区的闭环**。

## 一、市场机会与问题定义

### 1.1 被验证的需求：知乎最热的问题，都是人生选择

- 知乎上长期占据高互动量的问题，大量集中在**人生节点决策**：选科、专业、考研、考公、转行、城市、婚育
- 这类问题的共性是：**没有标准答案，但用户需要的不只是信息，是"有人和我一样纠结过"**
- 直接证据：项目事件库覆盖 15 个领域，其中教育、职业、财务、迁移、恋爱、家庭为高频主题

### 1.2 现有解决方案的结构性缺陷

| 现有形态 | 缺陷 |
| --- | --- |
| 读回答 | 单次消费、读完即走，无法转化为决策能力 |
| 知识付费课程 | 输出"正确答案"，与这类问题的本质（无标准答案）矛盾 |
| AI 问答助手 | 给出的是模型生成的通用建议，**不可溯源、不负责任、无法验证** |
| AI 角色扮演 | 人设讨喜但内容空洞，AI 会顺着用户说，**没有立场可言** |

**核心缺口：市面上没有任何一个产品，能让人在"有真实依据"的前提下，把一次人生选择完整地走一遍。**

### 1.3 时机

- 生成式 AI 使**大规模、低成本、可交互的叙事**第一次成为可能
- 知乎的开放平台与内容资产，使"有依据的叙事"第一次具备事实基础
- 【待补充：赛道数据与行业趋势引用】

## 二、产品与解决方案

### 2.1 一句话定义

> 一个你与知乎答主 AI 化身同行、在真实人生困境中做出选择、并承担后果的互动叙事产品。

### 2.2 核心循环

```
进入人生阶段 → 与四位同行者经历共同事件 → 做出关系选择（在意谁）
    → 做出人生选择（怎么做）→ 关系四轴变化 → 与化身自由对话
        → 后果在后续章节兑现 → 走向结局
```

### 2.3 三层价值

- **信息层**：真实困境 + 真实选项 + 真实依据（可溯源）
- **关系层**：四位有边界、有立场、会主动的同行者
- **反思维**：一局结束后可回顾的选择轨迹

## 三、核心创作思路

### 3.1 结构同构论（本产品的理论基石）

| 知乎 | 视觉小说 |
| --- | --- |
| 问题 | 困境 |
| 回答 | 选择 |
| 回答背后的人 | 选择背后的人 |

**结论：这不是"用知乎内容做个游戏"，而是"发现知乎本身就是一部视觉小说"。**

推论：知乎上每一个「你后悔当初的选择吗」，本质上都是一条已经存在的故事线。

### 3.2 三条设计原点

- **选择**：玩家选行动，不选成败——没有正确答案，只有承担
- **关系**：NPC 有自己的利益与边界，不因玩家选择而自动服从
- **化身**：玩家对话的不是虚构角色，是答主公开观点的可交互形态

### 3.3 反常识取舍

- **不做**知识问答游戏——知识不是被考察的对象，是关系的燃料
- **不做**AI 陪聊套壳——奖励不是答案，是选择

## 四、产品设计

### 4.1 人生阶段即剧本包

高中 / 本科 / 研究生 / 毕业到工作。每个阶段决定事件的现实边界、压力来源与关系线走向。

### 4.2 同行者体系

从答主化身池中选择 4 位同行者；叙事骨架为「共同篇 → 关系线（恋爱 / 友情）→ 结局」。

### 4.3 人生选择事件库

- 事件 = 真实困境 + 三个**行动机制不同**的选项（非同一方案的保守 / 中等 / 激进版本）
- 每个选项背后挂着真实知乎回答，作为该选项的**唯一事实源**
- 硬规则：**不存在低风险、低投入、多项高收益的支配选项**
- 后果表述：说明**谁看见了什么、谁承担了什么**，而非数值变化
- 好关系不等于永远加分：坦诚可能短期增加冲突，回避可能短期平静但损失信任

**已完成覆盖**：校园主线 10 条精编事件、30 个行动选项、90 条选项级知乎回答依据，覆盖高中、本科、硕士三阶段。

### 4.4 关系模型：四轴而非好感度

- **亲密 / 信任 / 冲突 / 承诺**四轴独立变化
- 外加"未解决的问题"随章节累积，不解决则反噬
- 信任无法用讨好换取；冲突不会因回避而消失

### 4.5 好感度 = 信息披露权限

| 档位 | 对方对你的了解 |
| --- | --- |
| 尚未分享 | 只能回应现场可见的事实 |
| 部分倾诉 | 只知道部分处境和一种担忧 |
| 完整分享 | 知道完整困境与依据，但不能替你做决定 |
| 共同决策 | 可提出异议、共同承担后果 |

### 4.6 结果由程序结算，情感由 AI 演绎

人生选择的后果由确定性结算产生，模型只负责把这件事讲述成故事。
**这是产品与"AI 写故事"类产品的根本分野：AI 无法为了讨好玩家而放水。**

### 4.7 完整视觉小说功能矩阵

对话、选择、Backlog、立绘表情、动作演出、音乐、自动 / 快进 / 跳过、多档存档、设置、全屏、隐藏 UI、时间回溯与分支。

### 4.8 结局与"人生答卷"

结局由关系轴与关系类型共同决定，多结局；一局结束后生成可回顾的选择轨迹。

## 五、答主 AI 化身系统

### 5.1 定义

**化身 = 答主公开内容的可交互形态**，不是虚构角色套答主名字。

### 5.2 三层真实性

| 层 | 内容 |
| --- | --- |
| 人设层 | 身份、领域、说话习惯 |
| 文风层 | 从该答主真实回答中习得的表达节奏 |
| 立场层 | 化身的观点必须能在他的知乎回答里找到依据 |

### 5.3 化身的分寸感（核心壁垒）

- **化身 ≠ 答主本人**：所有用户可见处标注为"基于知乎公开内容改编的虚构 AI 角色"；真实答主的姓名与账号不出现在任何用户可见数据中
  - *幻想的是关系，不是身份。*
- **模型不产出链接**：模型只声明"引用了哪几条"，URL 由程序从校验过的证据生成并规范化
  - 三重校验：入库校验 / 回答时校验 / 客户端再校验
  - 从机制上杜绝"AI 编造知乎链接"
- **先检索，后开口，且限额**：查不到时明确标注"未引用答主观点"，而非硬答
- **边界**：不读心、不越级披露、不知道尚未发生的事

### 5.4 化身的记忆与态度

- 记得玩家说过的话、做过的选择、回避过的问题
- 玩家的选择会改变化身对玩家的理解——是**态度**，不是数值

### 5.5 化身会主动找你

- NPC 有自己的目标与顾虑，会在章节之间主动发起对话
- **沉默也是一种行为**——想退缩时就不说话

### 5.6 自由对话真的影响关系

有据可依的交流才加分，泛泛而谈加分很少，查不到不加分；每位化身每局有上限。
**好感度只奖励有依据的交流。**

### 5.7 社交延展（灵魂匹配局）

- 化身之间也有关系，会互相评价
- 多人的数字分身可在同一场景中交谈
- 陌生玩家之间可按"你选了谁 / 你怎么选"互相看见

## 六、与知乎社区生态的契合度与场景价值

### 6.1 内容层：知乎是剧本的现实事实源

- 人生选择来自真实回答，保留可追溯来源与作者署名；不复制原文、不把真实答主写成虚构角色
- **每个选项旁边站着真实选过它的人**
  - 选项下方展示 2–3 位真实答主的头像与链接，标注「知乎用户也这么选了」，一键回到原回答
  - 决策瞬间具备社会临场感
- **主动对抗幸存者偏差**
  - 真实回答天然偏向成功叙事
  - 产品主动把失败与后悔的案例提升进结果集，而不是只呈现成功故事

### 6.2 人层：答主即化身

- 答主从"被阅读"变成"被需要"
- 个人 IP 获得可交互的新形态 → 答主具备自传播动机

### 6.3 关系层：社区关系的游戏化映射

关注 / 收藏 / 赞同 / 评论 → 同行者关系、信任、承诺。
玩家在游戏里重新理解"我为什么会关注这个人"。

### 6.4 反哺层：游戏产出回流社区（内容飞轮）

```
知乎真实回答 → 事件库 → 玩家选择 → 新的经验
    → 玩家产出知乎回答 / 想法 → 成为下一代事件库的养料 → 回到起点
```

- 结局可生成一篇知乎回答 / 想法：「我做过这个选择」
- 玩家选择聚合成"这一代人怎么选"的数据视图，对照真实答主分布

### 6.5 场景价值汇总

| 维度 | 价值 |
| --- | --- |
| 对用户 · 效率 | 把"翻 50 个回答"压缩成"活一遍" |
| 对用户 · 体验 | 从信息消费升级为情感消费 |
| 对答主 | 内容获得新形态与新读者 |
| 对知乎 · 内容质量 | 被选中的回答自带场景与因果，天然筛选高质内容 |
| 对知乎 · 生态 | 存量优质内容获得新消费场景与新的生产闭环 |

### 6.6 护城河：为什么这个场景只能在知乎成立

- 需要的不是"知识库"，是**真实的人在真实困境里的真实选择**
- 需要的不是"文风模仿"，是**可追溯、可署名、可回到原文的观点来源**
- 需要的不是"用户画像"，是**关注、收藏、赞同所构成的长期关系沉淀**

### 6.7 合规与伦理设计

> 本作不制造"答主的数字替身"，只制造"答主公开观点的可交互索引"。
> 温度来自表演，事实来自原文。

- 虚构标注贯穿全部用户可见面
- 引用可溯源、可点击、可回到原文
- 宁可说"资料不足"，也绝不编造答主的观点

## 七、技术实现与壁垒

### 7.1 三层架构

| 引擎 | 职责 |
| --- | --- |
| 叙事引擎 | 把已确定的事实写成人能读下去的剧情 |
| 世界模拟引擎 | 决定发生了什么、关系怎么变 |
| 化身引擎 | 在剧情之外维持一个像人、有边界、有依据的答主化身 |

### 7.2 生成协议：一句一推的流式叙事

逐条生成 → 逐条校验 → 逐条上屏，而非整段生成完再拆。
校验字段、说话者、顺序、单条长度、累计字数、选项规则；失败不污染已显示内容，只补剩余记录。

### 7.3 一致性保障

世界状态（角色、关系、物件、承诺、阶段）由程序持有，模型不得改写。

### 7.4 时间设计：让等待消失

> **我们不追求让 AI 更快，我们让等待发生在玩家本来就愿意停留的地方。**

| 手段 | 说明 |
| --- | --- |
| 阅读掩盖生成 | 实测单段生成 26–28 秒，玩家阅读一段需 45–60 秒，生成/阅读 ≈ 1:2 |
| 预取 | 玩家可能选的每条分支提前算好并缓存，做出选择时下一段已在等他 |
| 指纹复用与缓存 | 相同局面直接复用产物；请求在途去重；无关变化不失效缓存 |
| 短别名引用 | 用 `C1 / R1 / E3` 取代长 ID，消除模型幻觉重试（此前单章浪费 2 分钟以上） |
| 兜底而非祈祷 | 模型中途失败时，只要正文达标，程序自行收口，本段仍计为成功 |

**这不是性能优化，是产品结构上的时间设计。**

### 7.5 化身引擎

检索 → 立场 → 文风 → 生成 → 引用回执。引用来源需可校验，防止模型编造答主观点。

### 7.6 数据与隐私

- 密钥只在服务端，不进入前端与日志
- 存档最小化，演示数据定期过期
- 真实答主身份不出现在用户可见数据中

## 九、商业模式与增长路径

### 9.1 收入结构设想

- 【待测算】C 端：单次解锁 / 订阅制人生线
- 【待测算】B 端：与答主、出版方、教育机构的联名线
- 【待测算】平台侧：为知乎贡献内容消费时长与新内容产出

### 9.2 增长路径

1. **单点验证**：以答主化身作为传播单位，每位化身都是一次可传播的个人 IP 事件
2. **内容扩展**：以人生阶段与领域矩阵横向扩展事件库
3. **社区共创**：开放事件库，让答主与用户共同生产新困境
4. **社交裂变**：玩家选择的数据视图天然具备分享属性

### 9.3 冷启动优势

每个答主化身都是答主本人的一次"可交互化"，**答主有天然动机自传播**——这是本产品区别于一般游戏冷启动路径的关键。

## 十一、产品体验与设计感

- **视觉语言**：雨夜、暖金、低饱和紫；留白与呼吸感
