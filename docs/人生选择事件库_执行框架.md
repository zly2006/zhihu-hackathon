# 人生选择事件库执行框架

## 1. 目标

事件库提供可被游戏状态机消费、可追溯到知乎回答的人生困境。事件背景和三个选项都由知乎官方 CLI 检索；不复制知乎原文，不把真实答主写成角色，但必须保留回答 ContentID、作者、摘要和链接。

每条事件必须同时做到：

- 三个选项代表不同的行动机制，而不是同一方案的保守、中等、激进版本。
- 玩家选择行动，不直接选择成功或失败。
- 每个选项至少有 3 个不同 ContentID 的知乎回答，选择结果只能综合该选项的回答推导。
- 每个选项至少影响一名身边的人，关系影响落实到亲密、信任、冲突、承诺四轴。
- NPC 有自己的利益与边界，不因玩家选择而自动服从。
- 事件留下可在后续章节回收的旗标或故事钩子。

## 2. 数据流

```text
知乎官方 CLI（Answer only）
  -> 逐事件、逐选项检索并保留查询词
  -> 每个选项校验至少 3 条不同回答与可追溯链接
  -> 事件模板库
  -> 按年龄、领域、关系角色和前置旗标筛选
  -> 注入当前 WorldState 中的角色与具体状态
  -> 生成 ChapterChoice
  -> 玩家选择行动
  -> 模型只综合已选选项的 3 条知乎回答生成结果
  -> 固化 SimulationEvent 与 RelationshipChange
  -> 后续章节回收 delayed consequence / follow-up hook
```

事件模板不预写 AI 推断的结果。它定义困境和可选行动，并为每个行动保存独立的知乎证据快照；选择后，程序把对应回答作为唯一现实事实源注入模型，并校验模型回执的 ContentID 完全一致。

## 3. 单条事件质量门槛

### 结构硬约束

- 唯一 `id`，版本号为 2。
- 年龄范围合法，恰好 3 个选项，选项 ID 为 A/B/C。
- 三个 `strategyTag` 唯一。
- `sourcePolicy.mode` 固定为 `zhihu-answers-only`。
- 每个选项保留检索词、至少 3 条 `Answer`、不同 ContentID 和 `/question/.../answer/...` 链接。
- 模板不得包含 `immediate`、`delayed`、`flags`、`followUpHooks` 等预写结果字段。

### 编辑质量门槛

- 困境由一个具体时刻触发，不用“你要如何选择人生”一类空泛开场。
- 三个选项改变行动对象、资源投入或协作机制。
- 不存在低风险、低投入、多项高收益的支配选项。
- 好关系不等于永远加分：坦诚可能短期增加冲突，回避可能短期平静但损失信任。
- 后果文字说明谁看见了什么、谁承担了什么，而不只写数值变化。
- 重大关系变化需要相应的重要事件和后续回收。

## 4. 主题覆盖矩阵

当前正式校园主线使用 `content/campus-life-events.v1.json` 中的 10 条精编事件、30 个行动选项，覆盖高中、大学和研究生三个阶段。运行时不会再把旧的泛化人生事件库混入校园事件池；旧文件只作为历史素材保留。毕业到工作背景暂不注入校园事件，必须等有对应阶段的事件库后再开放，不能用研究生事件冒充职场事件。

知乎答主头像不是静态猜测字段。运行 `node scripts/enrich-zhihu-avatars.mjs` 会通过 `zhurl` 按回答 ID 读取 `author.avatar_url` 和答主主页；知乎要求登录时脚本会停止且不写入任何头像地址。回填完成后，事件校验器会检查头像必须来自 `zhimg.com`，主页必须是知乎 `people` 链接。

| 阶段 | 当前事件数 | 校园主题重点                                                                                     |
| ---- | ---------: | ------------------------------------------------------------------------------------------------ |
| 高中 |          3 | 选科与家庭期待、竞赛名额与共同成果、好友作弊与规则边界                                           |
| 本科 |          8 | 转专业、社团经费、小组作业、奖学金，以及异地、合住和毕业去向                                     |
| 硕士 |         13 | 论文署名、数据复现、实习与中期冲突、导师边界，以及毕业前后的关系与职业压力（含少量毕业后扩展线） |

本轮新增 10 条校园事件：高中 3 条、本科 4 条、硕士 3 条。原有 11 条现实议题保留，作为升学、实习、毕业和亲密关系压力的补充。

后续按以下维度补齐：

- 人生阶段：高中、本科、硕士；每批都分别检查年龄范围和校园语境，避免用职场标签代替硕士生活。
- 领域：教育、职业、财务、住房、迁移、创业、恋爱、婚姻、家庭、育儿、友情、健康、社交、失去、老去。
- 关系角色：父母、手足、伴侣、好友、室友、导师、同事、子女。
- 冲突机制：资源竞争、价值观差异、边界、照护责任、信息不对称、机会成本、长期承诺。

下一批优先补充班级干部与同学公平、宿舍作息与隐私、学生组织权力边界、交换机会、保研承诺、跨专业合作、导师更换、同门竞争、毕业去向与伴侣协商等主题。每个主题先写关系冲突和可回收后果，再写三个行动选项。

## 5. 分阶段执行

### Phase 1：知乎证据与首批种子（已完成）

- 通过知乎官方 CLI 建立 10 条事件、30 个选项、90 条选项级回答依据。
- 每个选项保留检索词、ContentID、作者、摘要和知乎回答链接。
- 产出可查询的事件库，不改 canonical 结算语义。

### Phase 2：运行时接入（已完成）

- 新版主线每局用故事 ID 制定稳定的高中、本科、硕士事件计划，同一存档读取时不重新抽取。
- 7 段剧情按“高中 2 段、本科 2 段、硕士 3 段”推进，只把当前事件注入模型提示词。
- 当前人物承担事件中的同学、好友、室友、伴侣或导师关系；未出场的父母、教师等只允许以无名身份进入旁白。
- 玩家选择后保存事件 ID、选项 ID 及三条证据快照；下一段只能综合这三条回答生成结果。
- 程序固定选项文本并要求模型输出 `[EVIDENCE]` 回执；ContentID 不完全一致时拒绝该段。
- 旧存档缺少事件计划时根据已选角色稳定补齐，不提升存档版本。

### 好感度与剧情融合

- 好感 0：困境仍是私事，NPC 只能观察现场外在变化。
- 好感 1：允许部分倾诉，只透露一种担忧，不展示全部依据。
- 好感 2：允许完整分享三条知乎依据，但 NPC 不能代替玩家决定。
- 好感 3 及以上：允许共同决策，NPC 可以提出异议、共同承担并在后续回收结果。
- 分享阶段由服务端状态计算并注入提示词，模型不得读心或越级披露。

### Phase 3：结算与回收

- 将选项后果边界注入 World Simulator。
- 延迟后果通过 story thread / flag 在 1 至 3 章后回收。
- 章末展示人物如何理解这次选择，而不只展示数值。

### Phase 4：扩充与验收

- 每批 10 至 20 条，人工审稿后入库。
- 用普通状态、低资源极端状态、关系高冲突状态分别测试。
- 连续运行 10 章，检查事件重复、关系吃书、无代价最优解和 NPC 工具人倾向。

## 6. 验收指标

- schema 校验通过率 100%。
- 每条事件三个行动机制均不同，每个选项至少 3 个可访问的知乎回答链接。
- 模型的证据回执与所选选项 ContentID 完全一致。
- 首批事件在领域、关系角色和代价类型上无明显同质化。
- 同一事件在不同 WorldState 下允许得到不同结果。
- 后续故事能够引用此前选择、关系变化和未解决问题。
